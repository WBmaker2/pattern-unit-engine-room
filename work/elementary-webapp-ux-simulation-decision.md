# Educational Simulation Decision

## 결정

이번 UX 개선에는 별도의 2D·3D·게임 시뮬레이션을 추가하지 않는다. `simulation: not-needed`로 기록한다.

## 근거

- 학습 목표는 반복 단위의 순서 찾기, 다음 칸 예측, 오류 수리, 모양 대응, 자기 규칙 만들기이다. 현재 DOM 목록·버튼·인라인 SVG 보드가 이 관계를 직접 표현한다.
- 미션은 결정적이고 입력도 토큰 선택과 순서 조작으로 한정되어 있어 물리 엔진이나 실시간 공간 모델이 학습 증거를 늘리지 않는다.
- 320px 모바일, 키보드, 스크린 리더의 읽기 순서, `prefers-reduced-motion`을 보장하려면 현재의 의미 있는 HTML/SVG가 가장 낮은 위험이다.
- 별도 캔버스나 WebGL을 도입하면 색·모양·무늬 대체 라벨, 포커스, 개인정보 경계를 다시 설계해야 하며 MVP 범위를 넓힌다.

## 검증 영향

- 별도 시뮬레이션 테스트 파일은 만들지 않는다.
- 대신 실제 learner path에서 각 판정 결과와 보드의 DOM 순서, `aria-label`, 키보드 포커스, 버튼 상태를 확인한다.
- 향후 시뮬레이션이 학습 목표를 직접 늘리는 요구가 생기면 먼저 별도 설계·접근성·성능 검토를 승인받는다.
